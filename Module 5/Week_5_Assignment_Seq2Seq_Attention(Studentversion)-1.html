Bridging the Gap: From Keras to Hugging Face¶

In Week 4, you built models by "wiring" layers together manually using Keras. You defined the input, hidden layers, and output, and then you told the model how to learn using .compile() and .fit().

This week, we are moving to Transfer Learning using the Hugging Face Trainer API. This can feel like a jump in complexity because the "training loop" is no longer visible—it is abstracted away. Use the mapping below to translate what you know (Keras) to what you are about to use (Hugging Face).

  • The Model: In Keras, you built the model step-by-step. In Hugging Face, you download a pretrained model (AutoModelForSeq2SeqLM.from_pretrained)

  • Configuration: Instead of model.compile(), you set hyperparameters in a config object called Seq2SeqTrainingArguments

  • The Loop: Instead of model.fit(), you initialize a Seq2SeqTrainer object and call trainer.train(). The Trainer automatically handles dynamic padding, learning rate decay, and GPU optimization.

Exercise:

  1. In the code, we set the max sequence length for articles to 512. Why don't we set it to 2,000 to capture the whole article? Explain how the Self-Attention mechanism's memory requirement scales with sequence length (Hint: is it linear or quadratic?).

The max sequence length was limited as a result of the multiplicative scaling of the attention mechanism. The attention matrix is max_sequence_length $N \times N$ max_sequence_length in size, which results in massive RAM requirements. This grows quadratically with sequence length.

  1. Discuss how excessive truncation might lead to a loss of the 'Lead-3' information.

Lead-3 information refers to the most important contextual information being present at the beginning of an article or body of writing. Excessive truncation could begin to remove this critical contextual information, reducing the information from which a model can learn.

def get_lead_3_baseline(text):
    try:
        sentences = nltk.sent_tokenize(text)
    except:
        # Fallback if NLTK fails or text is empty
        sentences = text.split(".")
        
    return " ".join(sentences[:3])

def get_zeroshot_summary(text, model, tokenizer):
    # Tokenize and move to device
    inputs = tokenizer(text, return_tensors="pt", max_length=input_max_len, truncation=True)
    inputs = {k: v.to(device) for k, v in inputs.items()}
    
    # Generate Summary IDs... Use 'no_grad' to save memory
    with torch.no_grad():
        summary_ids = model.generate(
            inputs["input_ids"],
            num_beams=4,
            max_length=128,
            min_length=30,
            early_stopping=True
        )
        
    # Decode IDs to Text
    summary = tokenizer.decode(summary_ids[0], skip_special_tokens=True)
    return summary

Exercise:

  1. Explain the 'Context Bottleneck.' Why do standard Seq2Seq models struggle to summarize articles when the most relevant information is buried in the middle of the text rather than the beginning?

In traditional Seq2Seq models like RNN or LSTM, the encoder layer distills the the sequence into a single, flat vector of a fixed size. The amount of information that can be compressed into this vector begins to reduce over time, resulting in less signal from contextually relevant information found later in the article. Even LSTM struggles; it can forget unneeded contextual inputs, but eventually the flat vector gets diluted with all of the additional sequential inputs.

Exercise:

  1. How does the predict_with_generate argument differ from standard training?

The predict_with_generate argument is critical for sequence to sequence generative training, as the model is fed a ground truth sequence input and attempts to predict the next sequence output token. This is the basis used to compute the losses, so the model is updated with how correct it's generated sequence prediction is.

  1. We configured the model to use Beam Search for generating summaries. Contrast Beam Search with Greedy Search. Why is Greedy Search highly likely to fail in a sequence-to-sequence summarization task, and how does Beam Search fix this?

Greedy search is a token based probabilistic mechanism, selecting only the most probable next token in the sequence. This is dangerous in sequence to sequence generation because it cannot backtrack and interpret the impact the next token has on the prior sequence, which can lead to erroneous dead ends in the generated sequence. Beam search, in contrast, keeps track of the N-highest probability sequences, which allows for more coherent sequential generation. Additionally, there are multiple paths through which the model can explore, selecting the most optimal for the final generated sequence.

import seaborn as sns
import torch

def aggregate_cross_attention(model, tokenizer, text, device="cuda"):
    """
    Runs a forward pass and extracts cross-attention weights for visualization.
    """
    model.eval()
    
    # Disable SDPA and force eager attention calculation... I really had to dig to find this solution
    # This forces the model to use the traditional math that saves the weights, resolving an error I was receiving
    model.config._attn_implementation = "eager"
    model.config.output_attentions = True
    
    # Tokenize input
    inputs = tokenizer(text, return_tensors="pt", max_length=input_max_len, truncation=True)
    input_ids = inputs["input_ids"].to(device)
    
    # Generate summary and return attentions
    with torch.no_grad():
        outputs = model.generate(
            input_ids,
            max_length=50,
            output_attentions=True, 
            return_dict_in_generate=True,
            early_stopping=True
        )
    
    # Extract generated tokens
    generated_ids = outputs.sequences[0]
    generated_tokens = tokenizer.convert_ids_to_tokens(generated_ids, skip_special_tokens=False)
    input_tokens = tokenizer.convert_ids_to_tokens(input_ids[0], skip_special_tokens=False)
    
    seq_len = len(generated_tokens) - 1 
    attention_matrix = torch.zeros(seq_len, len(input_tokens))
    
    for step in range(seq_len):
        last_layer_attn = outputs.cross_attentions[step][-1] 
        avg_head_attn = last_layer_attn[0].mean(dim=0).squeeze(0)
        attention_matrix[step] = avg_head_attn.cpu()
        
    return attention_matrix.numpy(), input_tokens, generated_tokens[1:]

Exercise:

1. The Mechanism: Describe how the Attention Mechanism you visualized allows the decoder to "bypass" the bottleneck of a single fixed context vector used in standard RNNs.

The Attention Mechanism bypasses the context bottleneck by allowing the decoder to "look back" at the hidden states of all input tokens at every single step of generation. Instead of receiving one static context vector, the decoder calculates a weighted sum of the encoder's hidden states, assigning high attention weights to the specific source words most relevant to the word it is currently trying to generate.
